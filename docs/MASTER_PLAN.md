# Eternal Forge — Master Plan

Status: PLANNED

## Vision

Eternal Forge is a browser-first idle action RPG designed around:

- effectively unlimited progression,
- deep build customization,
- competitive rankings,
- asynchronous progression,
- equipment theorycrafting,
- active and passive skills,
- prestige systems,
- long-term account development,
- guild cooperation,
- asynchronous PvP,
- seasonal content.

The game should be easy to understand initially but extremely difficult to
fully optimize.

A player should be able to:

- open the game for one minute,
- collect progress,
- upgrade something,
- leave,

or spend an hour:

- comparing equipment,
- optimizing skills,
- testing builds,
- crafting,
- analyzing rankings,
- planning progression.

---

# Core product principle

The game must not become:

"number increases automatically forever."

The player's decisions must matter.

A successful build change should sometimes produce more progression than
simply waiting longer.

Example:

change:
- weapon,
- three runes,
- passive nodes,
- skill modifier,

result:

+200 stages.

That creates meaningful theorycrafting.

# Competition

Competition is a core pillar.

The game should support multiple rankings rather than a single Power score.

Examples:

- Highest Stage
- Tower Floor
- Boss Damage
- Arena Rating
- Seasonal Points
- Speed Progression
- Survival
- Build-specific challenges
- Guild Ranking

Different builds should be strong in different activities.

---

# Character philosophy

The player does not choose a permanently fixed class.

Build identity emerges from:

- equipment,
- affixes,
- runes,
- skills,
- passive nodes,
- companions,
- prestige choices.

Possible archetypes:

Critical Berserker
Poison Assassin
Bleed Warrior
Lightning Knight
Fire Mage
Thorns Tank
Summoner
Life Steal Berserker
Freeze Control
Hybrid builds

These are examples, not hardcoded classes.

---

# Content philosophy

Systems should support enormous amounts of content.

But development should initially create a small content set.

Example:

Architecture:
supports thousands of passive nodes.

Initial content:
approximately 100.

Architecture:
supports thousands of item definitions.

Initial content:
approximately 50.

This prevents unnecessary content work before the underlying systems are fun.

---

# Progression philosophy

Progression should occur on multiple timescales.

Seconds:
combat.

Minutes:
equipment upgrades.

Hours:
stage breakthroughs.

Days:
build optimization.

Weeks:
prestige progression.

Months:
advanced prestige and competitive goals.

Long term:
seasons, guild progression and collection systems.

---

# Monetization principles

FUTURE.

Monetization must not be implemented during early development.

The architecture should not depend on monetization.

Avoid designing competitive systems around mandatory pay-to-win.

Potential future monetization areas can include:

- cosmetics,
- visual effects,
- skins,
- UI themes,
- supporter packs,
- convenience features that do not destroy competitive integrity.

A separate product/business decision will be made before monetization work.

# Success criterion

The core game succeeds when players repeatedly experience:

"I changed my build and unexpectedly pushed much further."

That experience is more important than visual spectacle.
